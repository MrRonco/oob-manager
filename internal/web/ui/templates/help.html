Help

Getting started

  1. The first admin account is created in the browser at /setup with the one-time setup code the container prints in its log on the first start (or on the server with the bootstrap-admin command). Everyone else gets a one-time setup link from an admin (Settings, Users).
  2. Servers are added in Settings, Servers: the BMC address (an IP literal), its kind, its TLS certificate fingerprint (confirmed once) and its logins, stored encrypted. They can also be listed in config.yaml (restart after editing).
  3. Compare the pinned TLS fingerprint with the one the BMC shows on its certificate page before you trust the data.
  4. Dashboards and monitors read the fleet with a read-only API token (Settings, API tokens).

Finding your way

  • The sidebar (the Menu button on a phone) lists Overview, Servers, Firmware, Events, Activity, Settings and Help, then every server with its state and one line about it.
    • {{- if .SignedIn}}
  • Go to lists every page, server and setting you can open, with a filter (also in the account menu).
    • {{- end}}
  • Every server page has the same tabs: Overview, Sensors, History, Events, Activity, Inventory and Security. Overview answers "is anything wrong?"; Sensors has every reading.
  • A server's actions are in three menus at the top of its pages, in the same place on every tab: Console (graphical and serial), Power (power actions and Restart BMC) and More (fan boost, maintenance, notes, the BMC's web interface). On a phone they sit in a bar at the bottom of the screen. Each menu works from the keyboard: Tab to it, Enter opens it, Escape closes it.
  • Activity lists what people and oob-manager did to the servers (power requests, fan leases, BMC restarts, maintenance), for every role. Sign-ins and settings changes are only in the admins' audit log.

Glossary

BMC
Baseboard management controller: the small computer inside a server that works even when the server is off (Dell iDRAC).
Redfish
The standard web API the BMC answers on. oob-manager reads it with a read-only account.
System Event Log (SEL)
The BMC's hardware log: power, temperature, fan, intrusion and memory events.
Lifecycle log
Dell's configuration and audit log: logins, firmware updates, settings changes.
Power-good (PG)
One bit per power rail, set when the rail is in range. Shown as Good or Fault, never as volts.
FQDD
Dell's fully qualified device descriptor, an internal name for a component.
Firmware view
The Firmware page lists what runs on each component, read from the BMC once a day, after a BMC restart, or when an operator presses Re-scan. It never updates firmware.
Running, previous and staged firmware
Running is the version the device reports now. Previous is the rollback copy the BMC keeps. Staged is an image that waits for a reboot to be applied.
Stored on the BMC
A firmware image the BMC holds in its own store but never installed (on Dell, the "Current" entry of the firmware inventory when it differs from the "Installed" one). A stored image newer than the running version is flagged Not applied; installing it from the BMC's update page clears the flag.
Vendor catalog
The vendor's signed list of firmware releases per server model (Dell's enterprise catalog). oob-manager downloads it only when the online check is on (Settings → General), or imports a copy an admin uploads, checks its signature first, and compares versions. It never downloads or installs firmware.
Criticality
The vendor's rating of a release: Urgent (flagged Urgent update and counted in the sidebar), Recommended or Optional (flagged Update available).
End of support
When the vendor catalog no longer lists a model, or only lists releases older than five years, updates cannot be checked; the server's update line says so instead of claiming it is up to date.
Minimum known good
The oldest version an owner accepts, set in config.yaml (firmware.minimum, and security.min_firmware for the BMC itself). Older versions are flagged Below minimum; versions that cannot be ordered are flagged Cannot compare.
Sensor history
The History tab draws every recorded sensor over 24 hours, 7 days, 30 days or a year, with the warning and critical levels of the focused temperature and the period's events. Every reading of each poll is kept for a week by default, then only summaries.
Bucket
One point of a history chart: the minimum, average and maximum of the readings in a fixed slice of time (10 minutes for 24 hours, an hour for 7 days, 3 hours for 30 days, a day for a year).
Rollup
The hourly and daily summaries (minimum, average, maximum, number of readings) the app keeps after the individual readings are deleted, so long ranges stay small. Settings → General sets how long each is kept.
Stale
The BMC has not answered for three poll intervals. Values stay visible but are marked as not current.
Step-up
A fresh authenticator code before a change. It stays valid for a few minutes, then you are asked again.
BMC restart
Restarts only the management controller (a server's Power menu, admin): consoles close and readings pause for a few minutes, while the host and its operating system keep running. A host restart is a power action and reboots the server itself.
Fan lease
A temporary minimum fan speed with a countdown, started from a server's More menu (Fan boost). The host fan script or the BMC applies it, and it ends by itself.
Headroom
How far a temperature is below its warning threshold. The bar marks warning and critical.

Keyboard

  • Every page starts with a "Skip to content" link.
    • {{- if .SignedIn}}
  • Ctrl+K (⌘+K on a Mac) opens Go to: type a few letters of a page, a server or a setting, then press Enter. g then o opens the Overview, g then s the Servers, and / jumps to the page's filter field. The single-key shortcuts can be switched off. All shortcuts.
    • {{- end}}
  • The graphical console captures the keyboard while it has focus. Press Ctrl+Alt+Shift to return focus to the console toolbar.
  • Escape closes an open menu.

Accessibility statement

oob-manager aims to meet WCAG 2.2 level AA in both color schemes, from 320 px wide phones to desktops, with keyboard alone and with a screen reader. Every page is checked with axe-core in automated tests.

Known limitation: the graphical console is a picture of the remote screen and cannot be read by a screen reader. The serial console (a server's Console menu) is the text, screen-reader friendly alternative where the BMC and the host support it.

Every status is shown as a word and a symbol, never by color alone. Pages work without JavaScript except the graphical console.

Motion is short (at most a quarter of a second), never used for alarms or status changes, and switched off completely when your device asks for reduced motion.

Supported hardware

Dell iDRAC8 and iDRAC9 over Redfish, and other Redfish BMCs for read-only health. IPMI is a legacy path. Virtual media, firmware updates, BIOS settings and BMC user management are out of scope by design.
