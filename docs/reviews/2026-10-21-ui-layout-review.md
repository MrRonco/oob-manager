# oob-console UI/UX and layout review

Reviewed: detached checkout of `main`, run with `make dev` (port 8444, because 8443 was already taken by another process) against the built-in mock BMCs (R730XD iDRAC8, R240 iDRAC9).
Method: Playwright 1.63.0 (Chromium) screenshots of every reachable page at 1440x900, 1280x800, 820x1180 and 390x844, in dark and light (OS `prefers-color-scheme`); axe-core 4.x (wcag2a/aa/21aa/22aa + best-practice) on 5 pages + login at desktop and phone, both schemes; keyboard tab-order probe; touch-target measurement; header and route probing. No tracked file was modified. Scripts were kept outside the repo.

Screenshot naming: `<page>-<viewport>-<scheme>.png` in a local folder outside the repository (not in git) (viewport = desktop|laptop|tablet|phone; scheme = dark|light). Files starting `SIMULATED-` are real pages with DOM edited in my own browser to show a state the mocks cannot produce (stale server, multi-page log). Nothing on the server was altered.

## 1. Verdict

A solid, honest foundation: server-rendered, zero JS, strict CSP, real landmarks, skip link, visible focus ring, labelled forms, and health always communicated as text plus colour. axe finds only two classes of issue. It is **not yet release-ready as a product**, for three reasons:

1. **It is a viewer, not a console.** One top-level nav item, no way to move between servers except the overview cards, no Settings/About/Help, no branding, no version. The IA must be restructured now, before power/fan/console actions and admin pages arrive.
2. **Staleness is communicated only partially.** The stale card still shows the last health badge (e.g. "OK") and the "Polled 15s ago" text is frozen at render time, so a page left open silently ages.
3. **Small but real accessibility/contrast defects** (light-mode primary button fails AA; horizontally scrolling tables are not keyboard-reachable) and several "no data" states that are indistinguishable from each other.

Pages not reachable in this build and therefore not screenshotted: TOTP enrolment reveal (QR/secret page; `Enroller` not wired, `/enroll` shows only the confirm form), 403/denied page (only an admin account exists; code review only), real stale/no-data (mocks cannot be stopped from outside the test binary; simulated), real pagination (mock logs have 15 entries, page size is 50; simulated), and logout (the 303 to `/login` works; the page it lands on is the login page already captured).

## 3. Proposed navigation and layout

Constraint: server-rendered templates + CSS only; navigation state comes from the route, not JS.

### Global header (all signed-in pages)

```
[logo] oob-console   Overview | Servers v | Logs | Settings*      [Auto-refresh: 60 s]   [admin v]
```

- **Overview** `/`: summary strip, Needs attention, server cards or table.
- **Servers** `/servers` (new index; also the dropdown content as a `<details>` menu): every configured server with health dot+label. This is the server switcher; the current server stays highlighted.
- **Logs** `/logs` (later): fleet-wide event feed (all servers, severity filter). Per-server logs stay under the server.
- **Settings** `/settings` (admin only; hidden for viewer/operator, route returns 403 with an explanatory page, audited).
- **User menu** (`<details>`): username, role chip, Preferences (theme, time zone, auto-refresh, units), Change password, Authenticator, Sign out. Sign out stays a POST form with CSRF.
- Footer on every page: version, Docs, Licences, About, Source.

### Server area `/servers/{id}`

Header: name, health badge, power state, age; breadcrumb `Overview / Servers / R730XD`. Then a tab bar with `aria-current`:

`Summary | Hardware (temps, fans, PSUs) | Logs (SEL, Lifecycle) | Inventory (System, Firmware, Licence, Capabilities) | Operations (later) | Console (later)`

- Actions (power, fan lease, console) live in an "Operations" tab plus a compact action bar in the header, disabled with a reason when the role or capability does not allow them. Dangerous actions go to dedicated step-up pages (`/servers/{id}/power`) with typed server name, not inline buttons.

### Settings area (admin only), `/settings`

Left sub-nav on desktop (a `<nav aria-label="Settings">` list), a top-of-page select-like link list on phone; no JS.

| Section | Path | Content |
|---|---|---|---|
| General | `/settings/general` | Instance name, default time zone, units, poll interval and stale threshold (read-only if set by config file), auto-refresh default, branding (logo/name placeholder) |
| Servers / BMCs | `/settings/servers` | List with health and last poll; add/edit server (name, address, vendor hint, credential ref, TLS pin, fan policy); "Test connection"; capability record; per-server tag (`critical`). Honours the read-only config mount: show as read-only with "managed by config.yaml" when so |
| Users | `/settings/users` | Users, roles (viewer/operator/admin), TOTP status, reset TOTP, lock/unlock, sessions, last sign-in |
| API tokens | `/settings/tokens` | Name, scope (read-only), created, last used, revoke; token shown once |
| Integrations | `/settings/integrations` | Graylog/GELF (delivery health), Homepage/Uptime Kuma/Prometheus endpoints and example snippets, Cloudflare Access mode |
| Audit log | `/settings/audit` | Filterable hash-chained audit (who, action, server, result), integrity check status, export (admin) |
| About | `/about` (also linked from every footer, all roles) | Version, build, licences, support/doc links |

Viewer and operator see **Preferences** and **Audit of own actions** under the user menu only, per the PRD role table.

### Page layout rules

- One `<h1>` per page, shared `page-head` component (title, status, age, actions).
- Status vocabulary fixed: Healthy/OK, Warning, Critical, Stale, No data, Unknown (health only). Always an icon glyph or word plus colour.
- `max-width` grows to ~96rem at >=1440 px for table views; cards stay in `auto-fit` grid; tables become stacked rows at <=40rem.
